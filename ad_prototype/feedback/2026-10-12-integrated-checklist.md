### 8.2 전체 메뉴 구조와 영역 책임

```text

  ├ 이미지 만들기 → 사진 → 설명 → 이미지 결과
  ├ 영상 만들기 → 사진 → 설명 → 영상 결과

사진 화면 → 선택 사항: 홍보할 곳 고르기
```

## 9. 재생성 및 크레딧 — 사용자 요청에 따른 향후 설계 기록

### 9.1 기록한 방향과 현재 상태

**최신 사용자 설명: 기능이 미완성이므로 금액·지급량·유형별 단가는 원가 확인 전 아이디어 수준의 가안으로만 보존한다. 영상 원가는 1회 약 400원이라는 사용자 예상이며 검증된 청구 금액이 아니다. 문구·이미지는 Gemini API 사용 예정이고 실제 모델 비용은 향후 확인한다.**

**구독 또는 크레딧 충전 후에는 문구·이미지(사진형 홍보물)·영상 모두 재생성이 가능하도록 향후 설계한다. 무료 계정은 세 유형 모두 재생성을 제공하지 않는다.** 영상만 단독으로 재생성을 금지하는 구조는 피하며 같은 이용 방식에서는 세 유형에 같은 원칙을 적용한다. 유료 이용의 유형별 비용 차이는 크레딧 차감량으로 표현한다.

이는 2026-10-12 사용자의 추가 요청으로 기록한 방향이며 교수님이 확정한 가격 정책이 아니다. **이번에는 문서만 기록한다. 재생성·크레딧·결제·횟수 제한 코드는 추가하거나 변경하지 않는다.** 현재의 내용 수정·새 홍보물 만들기·사진 변경·파일 재저장은 유료 재생성 구현으로 보지 않는다.

### 9.2 사용자 제시 최신 요금·사용량 가안 — 확정 상용 정책 아님

| 이용 방식 | 금액 가안 | 지급 크레딧 | 유효기간 |
|---|---:|---:|---|
| 매월 구독 | 월 9,900원 | 매월 15,000 | 지급분은 1개월 내 미사용 잔액 소멸 |
| 건당 크레딧 구매 1 | 8,900원 | 10,000 | 무기한(사용자 가안) |
| 건당 크레딧 구매 2 | 4,900원 | 5,000 | 무기한(사용자 가안) |
| 건당 크레딧 구매 3 | 1,990원 | 2,000 | 무기한(사용자 가안) |

**무료 계정 가안:** 영상 1회·포스터 3회·문구 10회로 유형별 최초 제작 횟수를 제한하며 **초기화하지 않는다. 무료 계정에서는 문구·포스터·영상 모두 재생성이 불가능하다.** 무료 사용량 소진 또는 재생성 요청 시 구독하거나 크레딧을 충전하도록 안내하는 방향이다. 유료 플랜은 공유 크레딧, 무료 계정은 유형별 제공 횟수로 구분한다. 한도 적용·소진 안내·재생성 제한·결제 전환은 현재 코드에 추가하지 않는다.

사용자의 `1,5000`·`1,0000` 표기는 각각 15,000·10,000크레딧으로 정리했다. 크레딧 수량과 원화 금액은 서로 다르다. 현재 플랜 UI는 여전히 가격·수량 준비 중을 표시하며, 이 가안을 코드에 반영하지 않았다.

| 콘텐츠 1건 사용량 가안 | 차감 크레딧 |
|---|---:|
| 문구 | 100 |
| 포스터/이미지 | 200 |
| 영상 | 1,000 |

이 최신 가안이 앞선 ‘문구 200크레딧’ 예시를 대체한다. 문구 1건·포스터 1건·영상 1건의 합계는 1,300크레딧이다. 월 구독 지급분 15,000에서 사용했다면 잔액은 13,700, 10,000 건당 구매분에서 사용했다면 8,700이다. 다른 유형을 함께 사용하는 공유 잔액이며 서로 독립된 생성 횟수를 별도로 지급하는 구조가 아니다.

동일 유형만 사용하는 경우의 산술상 최대 예시는 아래와 같다. 실제 기능에 적용된 생성 제한이나 보장 횟수가 아니다.

| 지급량 | 문구만(100/건) | 포스터만(200/건) | 영상만(1,000/건) |
|---|---:|---:|---:|
| 구독 15,000 | 150건 | 75건 | 15건 |
| 건당 10,000 | 100건 | 50건 | 10건 |

### 9.3 향후 화면·처리 후보 — 추가 결정 및 구현 필요

- 유료 이용의 각 결과 창에 같은 의미의 재생성 동작을 두고 실행 전에 해당 유형의 예상 차감량과 현재 잔액을 보여주는 안.
- 유료 영상에도 재생성 진입을 제공한다. 무료 계정의 재생성 불가, 잔액 부족이나 실행 중인 상태는 세 유형에 공통 원칙을 적용하고 이유·구독/충전 진입을 안내하는 안.
- 최초 생성·전체 유형 한 번에 생성·재생성·원본 사진 교체·기존 결과 재다운로드를 구분할 필요가 있다. 기존 파일 재다운로드를 새 생성으로 과금할지는 미확정이며 별도 결정한다.
- 요청 시작 때 크레딧을 예약하고 성공 때 확정 차감하며 실패·취소 시 예약을 해제하는 안. 중복 클릭·재시도·새로고침에서 이중 차감되지 않도록 서버 작업 ID와 처리를 설계하는 안. 사용자가 실패·취소 시 차감하지 않기를 선택했으며 예약·해제의 세부 기술 처리는 향후 구현한다.
- 기존 결과를 유지한 상태에서 새 결과를 받아 비교하는 안. 실패 시 기존 결과가 사라지지 않도록 해야 한다.
- 무료 제공량·초기화 없음·무료 재생성 불가·소진 시 유료 전환 안내, 구독·건당 지급량·금액, 유형 단가와 구독 지급분의 1개월 소멸은 사용자 가안으로 기록했다. 사용자가 건당 구매분 무기한, 구독 잔액 먼저 사용, 실패·취소 비차감을 선택했다. 읽어주기와 채널 선택도 현행을 유지한다. 한 번에 문구·포스터·영상 각 1건이면 단순 합계는 1,300크레딧이며 별도 묶음 할인 정책을 새로 가정하지 않는다.

## 12. 타사 조사 및 정책 상태

Runway·Luma·Adobe의 공식 크레딧 자료를 조회했다. 구독 월별 갱신과 추가 구매분 유효기간이 다르며 Runway는 추가 구매분 무기한, Luma는 12개월이다. 조사 출처·정확한 적용 플랜·원가 가정·비율 후보는 별도 조사 메모에 기록했다. 이 결과로 홍보잇다 가격을 확정하지 않는다.

## 13. GitHub 게시 전 최종 검토 — 이전 로컬 검토 이후 갱신

- 대상 브랜치: 원격에서 변경된 실제 이름 `feature/UI-Screen`. 로컬 이름과 추적 대상도 맞췄다.
- 입력 화면에서 ‘이름 선택 / 설명 필수 / 알리고 싶은 점 필수’를 보이도록 보완했다. 이름 없는 정상 진행과 기존 필수 입력 검증을 유지했다.
- 상단 우선순위·화면 책임 표에서 사용자 선택과 어긋나던 문구를 수정했다. 기존 홈 버튼·서비스 화면만 하단 메뉴·현행 채널 흐름 유지가 현재 기준이다. 별도 소개 화면·중복 버튼의 추가는 필요하지 않다.
- 최종 코드의 105개 화면 상태, 7개 너비 기능, 큰 글씨·긴 문구·짧은 화면, 메뉴14조합, 100/200% 확대 검사 및 빌드·타입 검사를 통과했다. [최신 검증과 캡처](2026-10-12-design-maintenance.md#2026-10-12-github-게시-전-최종-개선검증)를 같은 저장소에 보존했다.
